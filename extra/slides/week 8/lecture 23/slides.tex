\section{Persistence}
\begin{frame}{Persistence}
\vfill
So far ...
\begin{itemize}
	\item we know how to make programs;
	\item we know how to communicate our intentions to the CPU using conditional execution, functions, and iterations;
	\item we know that all our variables are stored in the main memory (RAM).
\end{itemize}
However, recall from Lecture 2 that once your computer is turned off, all RAM and CPU contents are gone.
\vfill
Specifically, we know that
\begin{itemize}
	\item the main memory (RAM) is volatile
	\item ... but our hard disk drive / solid state drive offers permanent storage.
\end{itemize}
\vfill
Even more, as soon as the Python interpreter quits, all your variables are gone.
\vfill
\end{frame}
%
\begin{frame}
\vfill
Today let's answer to the following questions:
\begin{enumerate}
	\item How can we read data from disk?
	\begin{itemize}
		\item we know how to create variables
		\item ... but we cannot always define our data "by hand"
	\end{itemize}
	\item How can we store our results permanently?
	\begin{itemize}
		\item we know how to show variables contents
		\item ... but it's not quite customary to screenshot your shell in order to share your results
	\end{itemize}
\end{enumerate}
\vfill
Focus on:
\begin{enumerate}
	\item Text files, such as the ones we can create with a simple text editor
	\item Pickle files
	\begin{itemize}
		\item Compressed Pickle files
	\end{itemize}
\end{enumerate}
\vfill
\end{frame}

\section{Reading Text Data}
\begin{frame}{Reading Text Data}
\vfill
Let' start by reading a text file which is stored on our disk.
\vfill
Python provides a built-in function called \texttt{open()} that takes care of opening a file.
\begin{table}[]
\begin{flushleft}
\begin{tabular}{ll}
\texttt{>{}>{}> fID = open("/path/to/file/myFile.txt", "r")} &  \\
\end{tabular}
\end{flushleft}
\end{table}
The \texttt{open()} function takes the following inputs:
\begin{enumerate}
	\item the path on your disk pointing to the file to be opened (i.e., \texttt{myFile.txt});
	\item the \texttt{"r"} flag, that means that file has to be opened in \textit{read mode}.
\end{enumerate}
and returns
\begin{enumerate}
	\item the file handle (i.e., \texttt{fID}).
\end{enumerate}
\vfill
\begin{block}{Note}
The file handle is not the actual data contained in the file, but instead it is a "handle" that we can use to read the data.
\end{block}
\vfill
\end{frame}
%
\begin{frame}
\vfill
\begin{block}{Warning}
If the file does not exist, \texttt{open()} throws an error and will not return any file handle.\\The current Python version has a dedicated error:\\
\texttt{\textcolor{red}{FileNotFoundError}: [Errno 2] No such file or directory: 'stuff.txt'}\\
or, in some older Python versions:\\
\texttt{\textcolor{red}{IOError}: [Errno 2] No such file or directory: 'stuff.txt'}\\
\end{block}
\vfill
\begin{block}{Hint}
Make sure that the file exists in the input path and/or make sure that you have set the input path correctly. The filename (with extension) must be included.
\end{block}
\vfill
\end{frame}
%
\subsection{\texttt{fID.read()}}
\begin{frame}
\vfill
\texttt{fID.read([size])} reads \texttt{size} characters (in raw format) from the text file:
\begin{itemize}
	\item it returns a unique string that contains the file contents
	\item if \texttt{size} is omitted, it reads the entire file
\end{itemize}
\begin{table}[]
\begin{flushleft}
\begin{tabular}{ll}
\texttt{>{}>{}> fID = open("/path/to/file/words.txt", "r")} &  \\
\texttt{>{}>{}> fileData = fID.read()} &  \\
\texttt{>{}>{}> print(fileData)} &  \\
\texttt{aa\textbackslash naah\textbackslash naahed\textbackslash naahing\textbackslash naahs\textbackslash naal\textbackslash naalii\textbackslash naaliis\textbackslash naals\textbackslash naar ...} &  \\
\texttt{dvark\textbackslash naardvarks\textbackslash naardwolf\textbackslash naardwolves\textbackslash naas\textbackslash naasvogel\textbackslash na ...} &  \\
\texttt{asvogels\textbackslash naba\textbackslash nabaca\textbackslash nabacas\textbackslash nabaci\textbackslash naback\textbackslash nabacus\textbackslash nabacu ...} &  \\
\texttt{ses\textbackslash nabaft\textbackslash nabaka\textbackslash nabakas\textbackslash nabalone\textbackslash nabalones\textbackslash nabamp\textbackslash nabam ...} &  \\
\texttt{pere\textbackslash nabamperes\textbackslash nabamps\textbackslash nabandon\textbackslash nabandoned\textbackslash nabandoning ...} &  \\
...[truncated output] &  \\
\texttt{>{}>{}> print(type(fileData))} &  \\
\texttt{str} &  \\
\end{tabular}
\end{flushleft}
\end{table}
\vfill
\end{frame}
%
\begin{frame}
\vfill
Under the hood, \texttt{read()} uses a header in order to keep track of the position within \texttt{fID}. If \texttt{read()} reaches the end of file \texttt{fID}, it returns and empty string. You can't go back (unless you re-open the file).
\vfill
\begin{table}[]
\begin{flushleft}
\begin{tabular}{ll}
\texttt{>{}>{}> fID = open("/path/to/file/words.txt", "r")} &  \\
\texttt{>{}>{}> fileData = fID.read()} &  \\
\texttt{>{}>{}> print(len(fileData))} &  \\
\texttt{1016511} \hfill \# we do have something in \texttt{fileData} &\\
\texttt{>{}>{}> fileDataAgain = fID.read()} &  \\
\texttt{>{}>{}> print(len(fileDataAgain))} &  \\
\texttt{0} \hfill \# we have an empty string! &  \\
\end{tabular}
\end{flushleft}
\end{table}
%\vfill
\begin{table}[]
\begin{flushleft}
\begin{tabular}{ll}
\texttt{>{}>{}> fID = open("/path/to/file/words.txt", "r")} &  \\
\texttt{>{}>{}> fileData = fID.read(10)} &  \\
\texttt{>{}>{}> print(fileData)} &  \\
\texttt{'aa\textbackslash naah\textbackslash naah'} \hfill \# first 10 characters in \texttt{fID} &\\
\texttt{>{}>{}> fileDataAgain = fID.read(10)} &  \\
\texttt{>{}>{}> print(fileDataAgain)} &  \\
\texttt{'ed\textbackslash naahing\textbackslash n'} \hfill \# 10 more characters from \texttt{fID} &  \\
\end{tabular}
\end{flushleft}
\end{table}
\vfill
\end{frame}
%
\begin{frame}
\vfill
\begin{block}{Note}
In the previous slide, the first call of \texttt{fID.read()} scanned the entire file until the end.\\
The second call sees nothing!\\
All file objects methods, including the ones we see today:
\begin{itemize}
	\item \texttt{fID.readlines()}
	\item \texttt{fID.readline()}
\end{itemize}
use an internal header to keep track of the position within the file.
\end{block}
\vfill
\begin{block}{Warning}
\texttt{fID.read()} loads the entire content of your file in the main memory.\\
Use it if at least one of the following holds:
\begin{itemize}
	\item the text file is small;
	\item the amount of RAM is sufficient for storing its entire contents.
\end{itemize}
The same facet also holds for \texttt{fID.readlines()}.
\end{block}
\vfill
\end{frame}
%
\subsection{\texttt{fID.readline()}}
\begin{frame}
\vfill
\texttt{fID.readline()} reads a single line from the text file.
\begin{table}[]
\begin{flushleft}
\begin{tabular}{ll}
\texttt{>{}>{}> fID = open("/path/to/file/words.txt", "r")} &  \\
\texttt{>{}>{}> fileData = fID.readline()} &  \\
\texttt{>{}>{}> print(fileData)} &  \\
\texttt{'aa\textbackslash n'} \hfill \# first line in \texttt{fID} &\\
\texttt{>{}>{}> fileData = fID.readline()} &  \\
\texttt{>{}>{}> print(fileData)} &  \\
\texttt{'aah\textbackslash n'} \hfill \# second line in \texttt{fID} &\\
\texttt{>{}>{}> fileData = fID.readline()} &  \\
\texttt{>{}>{}> print(fileData)} &  \\
\texttt{'aahed\textbackslash n'} \hfill \# third line in \texttt{fID} &\\
\texttt{>{}>{}> fileData = fID.readline()} &  \\
\texttt{>{}>{}> print(fileData)} &  \\
\texttt{'aahing\textbackslash n'} \hfill \# fourth line in \texttt{fID} &\\
\end{tabular}
\end{flushleft}
\end{table}
... and so on
\vfill
\end{frame}
%
\subsection{\texttt{fID.readlines()}}
\begin{frame}
\vfill
\texttt{fID.readlines([size])} reads the file contents in such a way that each line is a list item:
\begin{itemize}
	\item if the optional parameter \texttt{size} is given, whole lines totalling approximately \texttt{size} bytes (possibly after rounding up to an internal buffer size) are read
	\item if \texttt{size} is not given, it goes up until EOF (end-of-file)
\end{itemize}
\begin{table}[]
\begin{flushleft}
\begin{tabular}{ll}
\texttt{>{}>{}> fID = open("/path/to/file/words.txt", "r")} &  \\
\texttt{>{}>{}> fileData = fID.readlines()} &  \\
\texttt{>{}>{}> print(fileData)} &  \\
\texttt{['aa\textbackslash n', ...} \hfill \# first line in \texttt{fID} &\\
\texttt{'aah\textbackslash n', ...} \hfill \# second line in \texttt{fID} &\\
\texttt{'aahed\textbackslash n', ...} \hfill \# third line in \texttt{fID} &\\
\texttt{'aahing\textbackslash n', ...} \hfill \# fourth line in \texttt{fID} &\\
\texttt{'aahs\textbackslash n', ...} \hfill \# fifth line in \texttt{fID} &\\
\texttt{'aal\textbackslash n', ...} \hfill \# sixth line in \texttt{fID} &\\
... and so on until ... &\\
\texttt{'zymurgy\textbackslash n']} \hfill \# last line in \texttt{fID} &\\
\end{tabular}
\end{flushleft}
\end{table}
\vfill
\end{frame}
%
\subsection{Iterating Over a File}
\begin{frame}
\vfill
Finally, you can also read a file, line by line, by iterating over its handle with a very simple \texttt{for} loop.
\begin{table}[]
\begin{flushleft}
\begin{tabular}{ll}
\texttt{>{}>{}> fID = open("/path/to/file/words.txt", "r")} &  \\
\texttt{>{}>{}> for line in fID:} &  \\
\texttt{>{}>{}> \qquad print(line)} &  \\
%\texttt{['aa\textbackslash n', ...} \hfill \# first line in \texttt{fID} &\\
%\texttt{'aah\textbackslash n', ...} \hfill \# second line in \texttt{fID} &\\
%\texttt{'aahed\textbackslash n', ...} \hfill \# third line in \texttt{fID} &\\
%\texttt{'aahing\textbackslash n', ...} \hfill \# fourth line in \texttt{fID} &\\
%\texttt{'aahs\textbackslash n', ...} \hfill \# fifth line in \texttt{fID} &\\
%\texttt{'aal\textbackslash n', ...} \hfill \# sixth line in \texttt{fID} &\\
%... and so on until ... &\\
%\texttt{'zymurgy\textbackslash n']} \hfill \# last line in \texttt{fID} &\\
\end{tabular}
\end{flushleft}
\end{table}
At each loop iteration, a new line from the text file is fetched into \texttt{line}.\\
The \texttt{for} loop automatically stops when it reaches EOF.
\begin{block}{Note}
This is (possibly) the most efficient solution, especially when dealing with large text files since:
\begin{itemize}
	\item it's fully automatic
	\item each line is read, processed and then discarded.
\end{itemize}
\end{block}
\vfill
\end{frame}
%
\subsection{Final Remarks}
\begin{frame}
\vfill
It is customary to close the file after processing:
\begin{table}[]
\begin{flushleft}
\begin{tabular}{ll}
\texttt{>{}>{}> fID = open("/path/to/file/words.txt", "r")} &  \\
\texttt{>{}>{}> \# do something with fID} &  \\
\texttt{>{}>{}> fID.close()} &  \\
\end{tabular}
\end{flushleft}
\end{table}
If you do not close the file, Python automatically close it for you when the program ends.\\
If you feel you may forget to close the file, use the \texttt{with} statement:
\begin{table}[]
\begin{flushleft}
\begin{tabular}{ll}
\texttt{>{}>{}> with open("/path/to/file/words.txt", "r") as fID:} &  \\
\texttt{>{}>{}> \qquad \# do something with fID} &  \\
\end{tabular}
\end{flushleft}
\end{table}
and \texttt{fID} is automatically closed at the end of the \texttt{with} block.
\begin{block}{Note}
The \texttt{with} keyword is powerful. It can create context managers for several resources: scheduling threads for parallel processing, reading/writing data, exception handling and others. Yet it's quite an advanced topic.
\end{block}
\vfill
\end{frame}
%
\begin{frame}
\vfill
As you may have noted, every line is treated as a string (regardless of its content).

In order to parse the content of each line, you have to use
\begin{itemize}
	\item casting
	\item regular expressions
	\item string methods.
\end{itemize}
As the latter is concerned, notable examples include:
\begin{itemize}
	\item \texttt{s.rstrip([chars])}: returns a copy of a string \texttt{s} with trailing characters removed. \texttt{[chars]} specifies the set of characters to be removed. It defaults to whitespaces and escape characters (e.g., \texttt{\textbackslash n})
	\item \texttt{s.lstrip([chars])}: same as above, but it treats leading characters
	\item \texttt{s.strip([chars])}: same as above, but it treats both leading and tailing characters
	\item \texttt{s.split([char])}: splits a string \texttt{s} over a given \texttt{[char]}. It defaults to whitespaces.
\end{itemize}
\vfill
\end{frame}

\section{Writing Text Data}
\begin{frame}{Writing Text Data}
\vfill
In order to write data to a text file you first have to open a file:
\begin{table}[]
\begin{flushleft}
\begin{tabular}{ll}
\texttt{>{}>{}> fID = open("/path/to/file/myFile.txt", "w")} &  \\
\end{tabular}
\end{flushleft}
\end{table}
\vfill
The \texttt{open()} function takes the following inputs:
\begin{enumerate}
	\item the path on your disk where you file will be saved (i.e., \texttt{myFile.txt});
	\item the \texttt{"w"} flag, that means that file has to be opened in \textit{write mode}.
\end{enumerate}
and returns
\begin{enumerate}
	\item the file handle (i.e., \texttt{fID}).
\end{enumerate}
\vfill
\begin{block}{Warning}
If \texttt{/path/to/file/myFile.txt} already exists and you open it in write mode, all of its former contents are gone!
\end{block}
\vfill
\end{frame}
%
\begin{frame}
\vfill
Writing some data to a text file is just as easy as doing:
\begin{table}[]
\begin{flushleft}
\begin{tabular}{ll}
\texttt{>{}>{}> fID.write(<some content>)} &  \\
\end{tabular}
\end{flushleft}
\end{table}
For example:
\begin{table}[]
\begin{flushleft}
\begin{tabular}{ll}
\texttt{>{}>{}> fID.write("This is the first line \textbackslash n")} &  \\
\texttt{>{}>{}> fID.write("This is the second line \textbackslash n")} &  \\
\texttt{>{}>{}> fID.close()} &  \\
\end{tabular}
\end{flushleft}
\end{table}
\vfill
\begin{block}{Note}
\texttt{write()} argument must be a string. So make sure you cast your data to a string.
\end{block}
\begin{block}{Note}
You have to close the file especially when you open it in write mode to make sure that all your data are flushed to the disk.
\end{block}
\vfill
\end{frame}
%
\begin{frame}
\vfill
You can also add new contents to an already-existing file by opening it in \textit{append mode} (flag \texttt{"a"}):
\begin{table}[]
\begin{flushleft}
\begin{tabular}{ll}
\texttt{>{}>{}> fID = open("/path/to/file/myFile.txt", "a")} &  \\
\end{tabular}
\end{flushleft}
\end{table}
\vfill
If you open a file in append mode, any call to the \texttt{write()} method will write data to the end of the file.
\vfill
For example:
\begin{table}[]
\begin{flushleft}
\begin{tabular}{ll}
\texttt{>{}>{}> fID.write("This is a new line \textbackslash n")} &  \\
\texttt{>{}>{}> fID.write("This is another new line \textbackslash n")} &  \\
\texttt{>{}>{}> fID.close()} &  \\
\end{tabular}
\end{flushleft}
\end{table}
\vfill

\section{Pickle Files}
\begin{frame}{Pickle Files}
\vfill
Text files are a great option for saving your variables in a human-readable form.\\
But what happens when you have:
\begin{itemize}
	\item very complex lists-of-lists (or list-of-tuples)?
	\item very complex dictionaries?
	\item instances of a user-defined class?
\end{itemize}
It can be quite hard to parse these heterogeneous data structures into a text file.\\
Not to mention that in order to load them again, you have also to write a quite complex loader.
\vfill
In this regard, Pickle files are a great option.
\vfill
\end{frame}
%
\begin{frame}
\vfill
The \textcolor{red}{serialisation} process is a way to convert a data structure into a linear form that can be stored on disk or transmitted over a network.
\vfill
The Python \texttt{pickle} module allows you to serialise objects in a \textcolor{red}{binary} format:
\begin{itemize}
	\item[\cmark] the Pickle protocol allows to easily read (\textit{unpickle}) and write (\textit{pickle}) Python data objects with 1 line of code
	\item[\cmark] you can serialise the vast majority of Python objects, including:
	\begin{itemize}
		\item booleans
		\item integers, floats, complex numbers
		\item strings
		\item tuples, lists, dictionaries, sets (if they contain pickable objects)
		\item instances of user-defined classes
	\end{itemize}
	\item[\xmark] Pickle file contents are not human-readable: you can only read a Pickle file thanks to the \texttt{pickle} module in Python
	\item[\xmark] Pickle files are only Python-related: cannot be used in other programming languages
	\item[\xmark] the Pickle protocol changed across Python versions: unpickling a file that was pickled in a different version of Python may not always work properly
\end{itemize}
\vfill
\end{frame}
%
\subsection{Writing \texttt{pickle}s}
\begin{frame}
\vfill
In order to write a Pickle file, you must first \texttt{import} the \texttt{pickle} module:
\begin{table}[]
\begin{flushleft}
\begin{tabular}{ll}
\texttt{>{}>{}> import pickle} &  \\
\end{tabular}
\end{flushleft}
\end{table}
Then, choose the object(s) that you want to save, e.g. \texttt{Lnew}:
\begin{table}[]
\begin{flushleft}
\begin{tabular}{ll}
\texttt{>{}>{}> L = [1, 3, 10]} &  \\
\texttt{>{}>{}> Lnew = [ ]} & \\
\texttt{>{}>{}> for i in range(len(L)):} &  \\
\texttt{>{}>{}> \qquad Lnew.append(L[i] * 2)} &  \\
\end{tabular}
\end{flushleft}
\end{table}
and then, the magic happens:
\begin{table}[]
\begin{flushleft}
\begin{tabular}{ll}
\texttt{>{}>{}> outfile = open('myfile.pkl', 'wb')} &  \\
\texttt{>{}>{}> pickle.dump(Lnew, myfile)} &  \\
\texttt{>{}>{}> outfile.close()} &  \\
\end{tabular}
\end{flushleft}
\end{table}
What's going on in the last code snippet?
\begin{enumerate}
	\item we \texttt{open()} a file named \texttt{myfile.pkl} in \texttt{wb} mode (\textit{write binary}) and let \texttt{outfile} be its file handle
	\item we write \texttt{Lnew} to the file
	\item we close the file
\end{enumerate}
\vfill
\end{frame}
%
\begin{frame}
\vfill
You can also save multiple objects by "packing" them into a list or tuple, e.g.:
\begin{table}[]
\begin{flushleft}
\begin{tabular}{ll}
\texttt{>{}>{}> outfile = open('myfile2.pkl', 'wb')} & \\
\texttt{>{}>{}> pickle.dump([Lnew, L], outfile)} & \\
\texttt{>{}>{}> outfile.close()} &  \\
\end{tabular}
\end{flushleft}
\end{table}
\begin{block}{Warning}
When you read a file with a list/tuple that contains multiple items, you must remember their order!
\end{block}
\begin{block}{Note}
The \texttt{wb} flag is mandatory to tell Python to write a (serialised) binary file. Do not confuse \texttt{w} with \texttt{wb}!
\end{block}
\begin{block}{Note}
The file can be saved also without extension (i.e., \texttt{myfile} instead of \texttt{myfile.pkl}) and in principle you can also use the extension you prefer (i.e., \texttt{myfile.pickle} instead of \texttt{myfile.pkl}): Python will still understand that's a Pickle file.
\end{block}
\vfill
\end{frame}
%
\subsection{Reading \texttt{pickle}s}
\begin{frame}
\vfill
In order to read a Pickle file, you must first \texttt{import} the \texttt{pickle} module:
\begin{table}[]
\begin{flushleft}
\begin{tabular}{ll}
\texttt{>{}>{}> import pickle} &  \\
\end{tabular}
\end{flushleft}
\end{table}
\vfill
and then, the magic happens:
\begin{table}[]
\begin{flushleft}
\begin{tabular}{ll}
\texttt{>{}>{}> infile = open('myfile.pkl', 'rb')} &  \\
\texttt{>{}>{}> X = pickle.load(infile)} &  \\
\texttt{>{}>{}> infile.close()} &  \\
\end{tabular}
\end{flushleft}
\end{table}
\vfill
What's going on in the last code snippet?
\begin{enumerate}
	\item we \texttt{open()} a file named \texttt{myfile.pkl} in \texttt{rb} mode (\textit{read binary}) and let \texttt{infile} be its file handle
	\item we read the contents of \texttt{infile} into variable \texttt{X}
	\item we close the file
\end{enumerate}
\vfill
\end{frame}

\section{Compressing Pickle Files}
\begin{frame}{Compressing Pickle Files}
\vfill
If you have to save large data structures, Pickle files may take a lot of space on your hard drive.
\vfill
Workaround? \textcolor{red}{Compression}.
\vfill
Compression is the art of encoding (hence, saving) data with fewer bits in order to save disk space.
\begin{block}{Warning}
Do not confuse serialisation with compression!
\end{block}
\vfill
Since there is no free lunch, compression is driven by a trade-off:
\begin{itemize}
	\item saves disk space by encoding data with fewer bits
	\item the encoding stage can be costly (i.e., in terms of running times)
\end{itemize}
\vfill
\end{frame}
%
\begin{frame}
\vfill
Python in its standard library provides two well-known compression algorithms:
\begin{itemize}
	\item \textit{gzip}, in the \texttt{gzip} module
	\item \textit{bzip2}, in the \texttt{bz2} module
\end{itemize}
\vfill
Again, since there is no free lunch, compression algorithms themselves do have some trade-offs:
\begin{itemize}
	\item \textit{bzip2} is slower than \textit{gzip}
	\item \textit{gzip} yields files with larger size
\end{itemize}
\vfill
For the sake of example, let us consider \textit{bzip2} (although similar interfaces hold for \textit{gzip}).
\vfill
\end{frame}
%
\subsection{Writing a Compressed Pickle File}
\begin{frame}
\vfill
In order to write a compressed Pickle file with \textit{bzip2}, you must \texttt{import} both modules:
\begin{table}[]
\begin{flushleft}
\begin{tabular}{ll}
\texttt{>{}>{}> import pickle} &  \\
\texttt{>{}>{}> import bz2} &  \\
\end{tabular}
\end{flushleft}
\end{table}
Let's consider a big list:
\vspace{-0.3cm}
\begin{table}[]
\begin{flushleft}
\begin{tabular}{ll}
\texttt{>{}>{}> fID = open("words.txt", "r")} &  \\
\texttt{>{}>{}> fileData = fID.readlines()} & \# \texttt{fileData} is a list with 113783 words \\
\texttt{>{}>{}> fID.close()} &  \# we don't need \texttt{words.txt} anymore\\
\end{tabular}
\end{flushleft}
\end{table}
Now, let's save the list with \texttt{pickle}:
\begin{table}[]
\begin{flushleft}
\begin{tabular}{ll}
\texttt{>{}>{}> pickle.dump(fileData, open("words.pkl", "wb"))} &  \\
\end{tabular}
\end{flushleft}
\end{table}
Now, let's save the list with a \texttt{bz2}-compressed \texttt{pickle}:
\begin{table}[]
\begin{flushleft}
\begin{tabular}{ll}
\texttt{>{}>{}> bz2file = bz2.BZ2File("words.bz2", "w")} &  \\
\texttt{>{}>{}> pickle.dump(fileData, bz2file)} &  \\
\texttt{>{}>{}> bz2file.close()} &  \\
\end{tabular}
\end{flushleft}
\end{table}
\vfill
\end{frame}
%
\begin{frame}
\vfill
What's going on in the last code snippet?
\begin{enumerate}
	\item from the \texttt{bz2} module, we call \texttt{BZ2File} to create a file called \texttt{words.bz2} in \textit{write mode} (flag \texttt{w}). This yields a file handle named \texttt{bz2file}.
	\item we use the already-known \texttt{pickle.dump()} to save our variable \texttt{fileData}. However, instead of passing as argument a file handle obtained via \texttt{open()}, we pass the file handle obtained via \texttt{bz2.BZ2File()}
	\item we close the \texttt{bzip2} file.
\end{enumerate}
\vfill
Result?
\begin{itemize}
	\item \texttt{words.pkl} takes 1.2MB (=1200KB) on disk
	\item \texttt{words.bz2} takes 403KB on disk
\end{itemize}
The \texttt{bz2} file takes 1/3\textsuperscript{rd} of the space with respect to the original \texttt{pkl} file.
\vfill
\end{frame}
%
\subsection{Reading a Compressed Pickle File}
\begin{frame}
\vfill
In order to read a compressed Pickle file with \textit{bzip2}, you must \texttt{import} both modules:
\begin{table}[]
\begin{flushleft}
\begin{tabular}{ll}
\texttt{>{}>{}> import pickle} &  \\
\texttt{>{}>{}> import bz2} &  \\
\end{tabular}
\end{flushleft}
\end{table}
and then:
\begin{table}[]
\begin{flushleft}
\begin{tabular}{ll}
\texttt{>{}>{}> bz2file = bz2.BZ2File("words.bz2", "r")} &  \\
\texttt{>{}>{}> X = pickle.load(bz2file)} & \\
\texttt{>{}>{}> bz2file.close()} & \\
\end{tabular}
\end{flushleft}
\end{table}
What's going on in the last code snippet?
\begin{enumerate}
	\item from the \texttt{bz2} module, we call \texttt{BZ2File} to read a file called \texttt{words.bz2} in \textit{read mode} (flag \texttt{r}). This yields a file handle named \texttt{bz2file}.
	\item we use the already-known \texttt{pickle.load()} to import the contents of \texttt{bz2file} into a variable \texttt{X}. However, instead of passing as argument a file handle obtained via \texttt{open()}, we pass the file handle obtained via \texttt{bz2.BZ2File()}
	\item we close the \texttt{bzip2} file.
\end{enumerate}
\vfill
\end{frame}
